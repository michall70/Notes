你原来的脚本已经使用了 `make -j$(nproc)` 来利用所有 CPU 核心，这已经是不错的并行编译。不过还可以从几个方面进一步榨取硬件性能：

1. **更换更快的构建后端**：使用 Ninja 代替 Make，并行调度效率更高。  
2. **使用更快的链接器**：如 `lld` 或 `mold`，大幅减少链接时间（尤其是大型 C++ 项目）。  
3. **启用 ccache**：缓存编译产物，重复编译时几乎瞬间完成。  
4. **调整 I/O 优先级和内存限制**：避免编译时因磁盘或内存不足而卡顿。  

下面是优化后的脚本，并会逐行解释新增/修改的 bash 语法。

```bash
#!/bin/bash
# 启用严格模式：任何命令失败立即退出，未定义变量报错，管道中任意命令失败则整体失败
set -euo pipefail

# 获取脚本所在目录（源文件目录）
SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
cd "$SCRIPT_DIR"
echo "当前目录: $(pwd)"

# ---------------------------
# 可选优化：使用 ccache 加速重复编译
# 如果未安装，可以 sudo apt install ccache
if command -v ccache >/dev/null 2>&1; then
    export CC="ccache gcc"
    export CXX="ccache g++"
    echo "已启用 ccache 编译缓存"
fi

# ---------------------------
# 使用更快的链接器（需要提前安装 lld 或 mold）
# 检查 ld.lld 是否存在（通常来自 binutils 或 lld 包）
if command -v ld.lld >/dev/null 2>&1; then
    # 告诉 CMake 使用 lld 链接器
    export LDFLAGS="-fuse-ld=lld"
    echo "已启用 lld 链接器"
elif command -v mold >/dev/null 2>&1; then
    export LDFLAGS="-fuse-ld=mold"
    echo "已启用 mold 链接器"
fi

# ---------------------------
# 删除旧的 build 目录（如果存在）
if [ -d "build" ]; then
    echo "删除旧的 build 目录..."
    rm -rf build
fi

echo "创建 build 目录..."
mkdir build
cd build

# ---------------------------
# 使用 Ninja 作为构建后端（通常比 Make 更快）
# 检查 ninja 是否安装，未安装则退回到 make
if command -v ninja >/dev/null 2>&1; then
    GENERATOR="-GNinja"
    BUILD_CMD="ninja"
    # Ninja 默认使用全部核心，但可以显式指定并行数（例如核心数的两倍）
    PARALLEL_JOBS="$(( $(nproc) * 2 ))"
    echo "使用 Ninja 构建系统，并行作业数: $PARALLEL_JOBS"
else
    GENERATOR=""
    BUILD_CMD="make"
    PARALLEL_JOBS="$(nproc)"
    echo "使用 Make 构建系统，并行作业数: $PARALLEL_JOBS"
fi

# 运行 cmake 配置
echo "运行 cmake $GENERATOR .."
# 如果 GENERATOR 为空，下面这行相当于 cmake ..
cmake $GENERATOR ..

# cmake 成功则执行构建
if [ $? -eq 0 ]; then
    echo "cmake 配置成功，开始编译..."
    # 根据不同的构建命令执行并行编译
    if [ "$BUILD_CMD" = "ninja" ]; then
        ninja -j "$PARALLEL_JOBS"
    else
        make -j "$PARALLEL_JOBS"
    fi

    if [ $? -eq 0 ]; then
        echo "编译完成！"
        # 可选：安装（如果需要）
        # sudo make install
    else
        echo "编译失败，请检查错误信息。"
        exit 2
    fi
else
    echo "cmake 配置失败，请检查 CMakeLists.txt 或依赖项。"
    exit 1
fi
```

## 修改部分的 bash 语法详解

### 1. `set -euo pipefail`

- **`-e`** (errexit)：如果任何命令执行返回非零状态（错误），立即退出脚本。避免错误被忽略。
- **`-u`** (nounset)：如果使用了未定义的变量，立即报错并退出。例如不小心写了 `$undefined_var` 会直接停止。
- **`-o pipefail`**：在管道（`|`）中，只要任何一个命令失败，整个管道的返回值就是失败。默认只有最后一个命令的返回值生效。

### 2. `command -v ccache >/dev/null 2>&1`

- `command -v` 检查命令是否存在，比 `which` 更可靠（POSIX 标准）。
- `>/dev/null` 重定向标准输出到空设备（不显示）。
- `2>&1` 将标准错误（文件描述符2）合并到标准输出（1），也送到 `/dev/null`，彻底静默。

### 3. `export CC="ccache gcc"`

- `export` 将变量传递给子进程（如 cmake、make 调用的编译器）。
- `CC` 和 `CXX` 是 CMake 识别的 C 和 C++ 编译器环境变量。将 `ccache` 作为前缀，实际编译时先调用 `ccache` 缓存，再调用真正的编译器。

### 4. `export LDFLAGS="-fuse-ld=lld"`

- `LDFLAGS` 是链接器标志，会被 CMake 传递给链接阶段。
- `-fuse-ld=lld` 告诉 GCC/Clang 使用 `lld` 作为链接器（替换默认的 `ld`）。

### 5. `$(( $(nproc) * 2 ))`

- **`$(( ... ))`** 是 bash 的**算术扩展**，可以计算整数表达式。
- **`$(nproc)`** 命令替换，`nproc` 返回 CPU 核心数。外面套 `$(( ))` 做乘法，结果赋值给变量。
- Ninja 可以接受比核心数更多的并行作业（只要内存和 I/O 能承受），`核心数*2` 是常见激进值。

### 6. `if [ "$BUILD_CMD" = "ninja" ]; then`

- 字符串比较，注意变量用双引号括起来防止空格分裂。
- `=` 是字符串相等判断（POSIX 风格），`==` 也可用但不够兼容。

### 7. 使用 `$?` 判断上一条命令的退出码

- `$?` 包含上一个前台命令的退出状态。`0` 表示成功，非 `0` 表示失败。
- 可以在 `cmake ..` 后立即用 `if [ $? -eq 0 ]; then` 判断。

### 8. 不加双引号的变量展开（`cmake $GENERATOR ..`）

- 当 `GENERATOR` 为空字符串时，`cmake $GENERATOR ..` 会变成 `cmake ..`（正确）。但若 `GENERATOR` 包含空格（如 `-G "Unix Makefiles"`），不加双引号可能导致分词错误。此处 `-GNinja` 没有空格，安全。更严谨做法是用数组或 `eval`，但为简洁这样写可行。

## 使用建议

- **安装优化工具**：
  ```bash
  sudo apt install ninja-build ccache lld   # mold 可能需从 GitHub 下载
  ```
- **运行脚本**：保存为 `build.sh`，`chmod +x build.sh`，然后 `./build.sh`。
- **效果**：初次编译可能因 ccache 无缓存而略慢，后续重复编译会有明显加速；Ninja 和 lld 对大型项目效果显著。

如果你只想最小改动且确保稳定性，仅将 `make -j$(nproc)` 改为 `make -j$(nproc) -l $(nproc)`（负载限制），但以上方案更全面。根据你的项目规模和硬件内存，可灵活调整 `PARALLEL_JOBS` 的值（例如内存较小则保持 `$(nproc)` 甚至更少）。
