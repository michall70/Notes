## 一、SSH 不是论文特有的

**SSH不是SLAM-Former的某个功能，它是一个通用的远程连接工具**，就像你用微信联系朋友一样——微信不是某个人写的程序特有的，谁都可以用。

**你只需要知道两点**：
1. SSH是Linux/服务器自带的，**不需要任何源码支持**
2. 你跑的每个程序只要在服务器上，都能通过SSH连接上去操作

那个 `ssh -L 8080:localhost:8080` 是SSH自带的一个"附加功能"（端口转发），跟SLAM-Former没关系，换成其他任何需要看网页的程序（比如Jupyter Notebook）都是同样的用法。

然后输入密码。

### 步骤2：在服务器上跑SLAM-Former

SSH连上后，你敲的**每一行命令都是在服务器上执行的**：

如果你用**MobaXterm**（Windows）：它自带X11转发，`--vis` 弹的窗口会自动显示在你的电脑上。

## 一、操作服务器是不是只能用终端？

**是，也不是。**

绝大多数情况下，你确实只有一个黑乎乎的终端。但这**不代表不能传文件、不能看图**。终端只是"文字通道"，但你可以通过它在服务器上运行各种命令来完成任务。

类比：你人在北京，要遥控一台在上海的电脑。你的"遥控器"就是一个文字聊天框（终端/SSH），但你可以通过这个对话：
- 让上海电脑下载文件（用 `wget`）
- 让上海电脑运行程序（敲命令）
- 让上海电脑把结果传回来（用 `scp` 或 `rsync`）

## 二、传输文件怎么办？

### 方法1：最简单——scp（跟ssh一样自带）

```bash
# 从你的电脑 上传文件 到服务器
scp /本地路径/文件名 用户名@服务器IP:/目标路径/

# 从服务器 下载文件 到你的电脑
scp 用户名@服务器IP:/服务器上的文件 /本地路径/
```

**真实例子**：
```bash
# 把本地的 test.png 上传到服务器上
scp ~/Desktop/test.png root@123.45.67.89:/home/user/

# 把服务器上的结果下载到本地
scp root@123.45.67.89:/home/user/output/final.ply ~/Downloads/
```

**需要输入密码**（每次都要输，或者可以配免密登录）

### 方法2：传文件夹——rsync（断点续传，大文件推荐）
```bash
rsync -avz 本地文件夹/ 用户名@服务器IP:/目标路径/
```

### 方法3：图形化工具（推荐新手）
- **FileZilla**：免费，图形界面，左侧本地文件，右侧服务器文件，直接拖拽
  - 协议选 SFTP，主机填服务器IP，端口 22，输入用户名密码
- **VS Code 插件 Remote-SSH**：装好后，用VS Code打开远程文件夹，**像操作本地文件一样拖拽、编辑**

## 三、服务器怎么知道要发送什么到8080端口？

这个问题问得特别好，因为这恰恰是**新人最大的认知盲区**。

### 核心概念：端口就是一个"门牌号"

你的服务器只有一个IP地址（比如 `123.45.67.89`），但上面可能同时运行着几十个服务：

| 端口 | 服务 | 类比 |
|------|------|------|
| 22 | SSH（你连上去的终端） | 大门 |
| 80 | 网页服务（HTTP） | 快递收发室 |
| 8080 | 你手动启动的网页服务 | 临时租的储物柜 |
| 3306 | 数据库 | 地下保险库 |

**服务器不会"自动知道"发什么到8080**。而是**你手动启动了一个程序，它说"我要占用8080端口"**。

### 具体流程（以 SLAM-Former 为例）：

```bash
# 你在服务器上敲了这行
python slam/visualize_results.py --result_dir ./output/result --port 8080
```

这句话在干什么？

```
你敲的命令 
    ↓
服务器操作系统  → 分配8080端口给这个程序  → 程序开始监听8080
    ↓
任何发到 服务器IP:8080 的请求
    ↓
操作系统把请求转给这个Python程序
    ↓
程序读取 result_dir 里的 .ply 文件
    ↓
程序返回一个3D网页给你
```

**关键理解**：不是服务器"知道"发什么，而是**你主动启动的程序告诉操作系统"我要占用8080，有东西发过来就交给我处理"**。

### 但是有一个问题

服务器**默认不允许外部访问8080**（防火墙规则）。所以如果直接在你的电脑浏览器输入 `服务器IP:8080`，很可能打不开。

这就引出了你的下一个问题——

## 四、端口转发/映射是什么意思？

### 直观比喻

想象服务器在**一栋有保安的大楼里**（防火墙），普通快递（外部访问）进不去8080房间。

**SSH端口转发**就是：你**开了一条专属密道**，从你的电脑直通服务器里的8080房间：

```
你的浏览器 → 你电脑的8080端口
                    ↓
               SSH软件打包转发
                    ↓
               通过加密通道传到服务器
                    ↓
               服务器SSH收到，转给localhost:8080
                    ↓
               你的Python程序收到请求，返回3D网页
                    ↓
               原路返回给你的浏览器
```

### 命令逐字解释

```bash
ssh -L 8080:localhost:8080 user@remote-server
```

逐个拆开：

| 部分 | 含义 |
|------|------|
| `ssh` | 启动远程连接工具 |
| `-L` | 告诉SSH："我要做一个端口转发（Local，本地的）" |
| `8080` | 你**自己电脑**的8080端口（你浏览器访问的地方） |
| `:` | 分隔符 |
| `localhost` | 指的是**服务器那台机器**（在SSH语境里，"本地"是指服务器的本地，容易混淆） |
| `:8080` | 服务器上的8080端口 |
| `user@remote-server` | 要连到哪台服务器 |

**完整翻译**：SSH啊，你帮我开一条通道：任何人访问**我电脑的8080端口**，麻烦你通过加密连接，帮我转发到**那台服务器的8080端口**上。

### 一个更直白的类比

这就像：
1. 你在**服务器**上喊一嗓子："我开了一个3D网页查看器，在8080等着！"
2. 但服务器在**防火墙后面**，外面的世界听不到
3. 你跑 `ssh -L 8080:localhost:8080 user@server`
4. SSH就在**你的电脑和服务器之间打了一条电话线**
5. 现在你在浏览器上访问 `http://localhost:8080`
6. 这个请求就顺着电话线传到了服务器上的程序
7. 服务器把3D网页顺着电话线传回来给你

## 五、你现在实际操作需要做什么

在Ubuntu上，一句话总结所有步骤：

```bash
# 1. SSH连上服务器（会进入远程终端）
ssh user@服务器IP
# 输入密码

# 2. 在服务器上启动查看器
python slam/visualize_results.py --result_dir ./output/result --port 8080

# 3. 保持上面那个终端开着，另开一个Ubuntu终端（快捷键 Ctrl+Alt+T）
# 在新终端里运行端口转发
ssh -L 8080:localhost:8080 user@服务器IP
# 输入密码（需要保持这个窗口也开着）

# 4. 打开浏览器，访问 http://localhost:8080
# 就能看到SLAM-Former的3D重建结果了
```

**如果嫌麻烦**：把所有文件下载到本地用Open3D看：
```bash
# 在本地终端
scp -r user@服务器IP:./output/result/final.ply ~/Downloads/
```
然后在本地用 `open3d` 或 CloudCompare 打开 `.ply` 文件看。
