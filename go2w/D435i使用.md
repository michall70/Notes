# 过程中的两个问题，值得记住

**1. 狗连不上外网 → 包只能从笔记本传过去**

狗在 `192.168.123.x` 内网，公网完全不通，`apt install` 会一直卡住下载。所以流程变成：

```
笔记本(有网) 下载 .deb  →  scp 传过去  →  狗上 dpkg -i
```

还要注意：**狗是 arm64（Jetson），笔记本是 x86_64**。两个架构的 `.deb` 不能混用，我下的是 `_arm64.deb` 那一版。

**2. fastrtps 在这台 Jetson 上会 `bad_alloc`**

用默认中间件时，`ros2 topic echo` 一直报错，读不出数据。换成 CycloneDDS 立刻正常 —— **和你之前在狗上踩过的那个问题根因相同**。

所以 `rs_env.sh` 里那几行不能省。

# 话题
抓到了真实内容。**8 个话题其实是 4 类**：

| 话题 | 消息类型 | 里面装什么 |
|---|---|---|
| `color/image_raw` | `Image` | 彩色图，`rgb8`，1280×720，每像素 3 字节 |
| `depth/image_rect_raw` | `Image` | 深度图，`16UC1`，848×480，每像素 2 字节 |
| `color/camera_info` | `CameraInfo` | 彩色相机的内参 K + 畸变 D |
| `depth/camera_info` | `CameraInfo` | 深度相机的内参 K + 畸变 D |
| `color/metadata` | `Metadata` | 曝光/增益等 JSON 串，调试用 |
| `depth/metadata` | `Metadata` | 同上 |
| `extrinsics/depth_to_color` | `Extrinsics` | 深度相机 → 彩色相机的 R 和 t |
| `imu` | `Imu` | 角速度 (rad/s) + 线加速度 (m/s²) |

# 三个必须记住的点

## ① 深度图的值是**毫米**，不是米

实测那个话题的 `encoding` 是：

```
encoding: 16UC1     ← 16位无符号整数，单通道
```

所以每个像素是一个 `uint16`，值是**距离多少毫米**。`0` 表示**测不到**（黑色物体、玻璃、太远、反光）。

你以后写 `depth / 1000.0` 才是米。这个坑几乎所有人都会踩一次。

## ② `camera_info` 的 `K` 是“3D 点 ↔ 像素”的换算表

实测深度相机的 K：

```
k: [ 424.40,    0,    421.58,
        0,   424.40,  240.31,
        0,       0,      1   ]
```

它其实就是 `fx, cx, fy, cy`。用途是：

```
u = fx * X / Z + cx
v = fy * Y / Z + cy
```

反过来，知道像素 `(u,v)` 和它的深度 `Z`，就能算回 3D 点 `(X,Y,Z)`——**这一步就是从深度图生成点云的全部内容**。

顺带一提：`d`（畸变系数）全是 0。因为 D435i 出厂每台都做过标定，给你的是**已经去过畸变**的图（`rect_raw` 的 raw 指“原始深度”，不是“原始图像”）。

## ③ 深度图和彩色图**像素不对应**

深度 848×480，彩色 1280×720 —— 尺寸都不一样，同一个像素坐标在两边的含义完全不同。

原因是 `align_depth.enable` 默认是 **false**。想让深度图“贴”到彩色图上，得把这个参数打开，才会多出 `/camera/aligned_depth_to_color/image_raw` 这类话题。

另外看一眼 `frame_id`：

```
camera_color_optical_frame
camera_depth_optical_frame
```

**optical** 是有讲究的：这种坐标系是 **z 朝前、x 朝右、y 朝下**，和 ROS 常规的 x前/y左/z上 不同。后面接 SLAM 时坐标轴搞反，地图会翻过来。
